TASK: P1-T2 — Provider Interface & OpenRouter Client

═══════════════════════════════════════════════════════════════
OBJECTIVE
═══════════════════════════════════════════════════════════════
Create the base provider interface and implement the OpenRouter HTTP client.
This ensures we have a fully functional E2E passthrough system in Phase 1
without relying on mock endpoints.

═══════════════════════════════════════════════════════════════
CONSTRAINTS & RULES
═══════════════════════════════════════════════════════════════
- Target files: `smartrouter/router/base_provider.py`, `smartrouter/router/clients.py`
- Define an abstract base class `BaseProvider` with an async `generate` method.
- Implement `OpenRouterClient` that inherits from `BaseProvider`.
- Use `httpx.AsyncClient` to forward the `ChatCompletionRequest` to OpenRouter's `/v1/chat/completions` endpoint.
- Ensure the API Key is read from `os.getenv("OPENROUTER_API_KEY")`.

═══════════════════════════════════════════════════════════════
IMPLEMENTATION HINTS
═══════════════════════════════════════════════════════════════
- The OpenRouter URL is `https://openrouter.ai/api/v1/chat/completions`.
- Pass the required OpenRouter headers: `Authorization: Bearer <key>`.
- The `generate` method should take a `ChatCompletionRequest` model and return a `ChatCompletionResponse` model.
